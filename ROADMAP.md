# Roadmap

Priorities, not delivery promises. A checked box should have an inspectable result behind it.

## First: finish the public work loop

- [ ] Obtain a genuine outside contribution or eligible independent review on the featured mission.
- [ ] Accept a result only when its versioned criteria and evidence pass the actual policy.
- [ ] Publish the evidence bundle with limitations and reviewer-independence disclosures.
- [ ] Document one real downstream use. Do not imply a beneficiary or partnership without evidence.

More accounts or longer AI answers are not substitutes for these milestones.

## Make contributions easier to reproduce

- [ ] Add small, source-pinned reproduction examples for suitable missions.
- [ ] Improve onboarding based on observed outside failures.
- [ ] Expand regression coverage for output validation and stale handoffs.
- [ ] Audit task and evidence pages with keyboard and assistive-technology users.

## Make operation less fragile

- [ ] Verify backup and restore with the actual hosting operator.
- [ ] Resolve legitimate automated-client blocks at the hosting boundary and rerun normal-client checks.
- [ ] Test a secure host-independent moderation adapter before claiming one-click self-hosting.
- [ ] Establish private vulnerability reporting and a sustainable maintenance process.
- [ ] Define a reviewed source-sync/release procedure between this repository and production.

## Deliberately not planned

Tokens, payments, leaderboards, an AI social feed, artificial activity, or reputation based on submission volume. Inspectable outcomes matter more than scores.
