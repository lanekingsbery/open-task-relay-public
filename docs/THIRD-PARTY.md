## Existing components retained

The direct inventory covers the existing Drizzle ORM/Kit (MIT), Tailwind (MIT), TypeScript (Apache-2.0), ESLint (MIT), shadcn/Base UI/Radix component ecosystem (MIT), Lucide (ISC), and smaller UI helpers. Node's standard test runner, Web Crypto and WHATWG URL/fetch avoid new runtime packages for tests, secret generation, URL parsing and clients. The existing local SDK source remains project MIT code; its HTTP behavior is tested without automatic write retries.

Optional image packages deserve explicit treatment: the lockfile includes Sharp/libvips platform variants, including LGPL-bearing optional WASM bundles. They are inherited through the existing toolchain; they are **not included in this Worker/client build**, which uses the existing Cloudflare image binding. No libvips code was copied or modified. Do not redistribute those native/WASM binaries under the project MIT notice or introduce them into the deployed bundle without a separate license review. The new permissive-license PR gate intentionally flags such dependency changes for examination.

The read-only client-access probe additionally used [Requests](https://github.com/psf/requests) 2.34.2 (Apache-2.0), installed only in scratch for testing, not as an application dependency. Its dependencies were idna 3.19 (BSD-3-Clause), urllib3 2.7.0 (MIT), charset-normalizer 3.5.1 (MIT), and certifi 2026.7.22 (MPL-2.0 CA bundle). No probe dependency or CA bundle is distributed with the application.

## September 13 dependency review

The public repository has two workflows: source checks and dependency review. Checkout 7.0.1 and setup-node 7.0.0 are pinned by commit in both the source-check workflow and its public-export template. The Node 24 runner requirement is compatible with `ubuntu-latest` and `.nvmrc`. Checkout's credential-storage change does not affect `persist-credentials: false`; its safer privileged-fork defaults remain enabled. Neither workflow checks out PR code through `pull_request_target` or `workflow_run`. Setup-node's ESM migration is internal to the action; the workflow already explicitly uses npm caching and has no removed `always-auth` input, registry authentication, publishing, or deployment steps. Read-only permissions remain unchanged. See the [checkout changelog](https://github.com/actions/checkout/blob/v7.0.1/CHANGELOG.md) and [setup-node migration notes](https://github.com/actions/setup-node/blob/v7.0.0/README.md).

Tailwind and its PostCSS plugin are upgraded together to 4.3.3. Lightning CSS 1.32.0 and its platform packages are unmodified build-time dependencies, not application imports. MPL tooling was already present in the previous lockfile, including Vite's separate Lightning CSS version. The failed check was our permissive-only allowlist, not evidence of an inherent MIT/MPL incompatibility.

The existing MPL-2.0 allowance is appropriate for this use. MPL permits a larger work under other terms while preserving the MPL-covered files' terms. OTR's original files remain MIT. Generated CSS does not incorporate the compiler implementation. The public manifest excludes `node_modules`, and the source archive contains project source and dependency metadata, not Lightning CSS binaries or source. No compiler modifications are made. If distributing those libraries or binaries later, preserve notices and MPL terms, provide the corresponding covered source (including modifications), and inform recipients how to obtain it; do not label that dependency MIT. These obligations apply to covered files, not all independent OTR source. See [MPL sections 3.1–3.4](https://www.mozilla.org/en-US/MPL/2.0/), [Mozilla's distribution FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/), and [Lightning CSS 1.32.0 source and license](https://github.com/parcel-bundler/lightningcss/tree/v1.32.0). Other unapproved licenses and high/critical vulnerabilities still fail dependency review.

Recharts 3.10.1 is referenced only by the reusable chart component and its component test; no application route imports it. The shipped declarations retain `align` and `verticalAlign` as deprecated props alongside the new `position`/`offset` API, so the existing Legend wrapper needs no adaptation. Animation and positioning changes therefore do not alter an active OTR chart. The npm release contains prebuilt CommonJS, ES module and type entry points, supports React 19, and has no install/postinstall hook. Its maintainer `prepare`/build scripts and repository Windows development-install notes do not require building a registry install from source. The lockfile's Immer 11 and reselect deduplication are internal to Recharts; OTR imports neither directly. Registry integrity/provenance and clean installation are checked separately from application behavior. See [3.9 release notes](https://github.com/recharts/recharts/releases/tag/v3.9.0), [3.10 release notes](https://github.com/recharts/recharts/releases/tag/v3.10.0), and [3.10.1](https://github.com/recharts/recharts/releases/tag/v3.10.1).

## Security findings

`npm audit` fell from 23 findings (17 high, 5 moderate, 1 low) to **4 moderate, 0 high, 0 critical**. The four reported package nodes share [GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99): Drizzle Kit → deprecated esbuild-kit loader/core-utils → old esbuild. The advisory concerns esbuild's development-server CORS behavior; this project uses that nested dependency for configuration loading, not a public development server. This exposure assessment is an inference from the dependency path and command usage, not a waiver or proof of unreachability.

`npm audit --omit=dev` reports **zero known runtime findings**. npm's suggested force-fix downgrades Drizzle Kit to 0.18.1; it was not applied because it would change migration tooling across incompatible versions. Revisit a supported Drizzle upgrade with migration compatibility testing. CI gates all high/critical findings; moderate findings remain visible. No zero-risk or comprehensive security-audit claim is made.

Registry verification on the clean public checkout: `npm audit signatures` verified **682 registry signatures** and **250 provenance attestations**. This verifies supplied provenance/integrity metadata, not source behavior.

## September 20 dependency reconciliation

The operational repository imports the public repository's previously reviewed Base UI 1.8.0, Lucide 1.41.0, Recharts 3.10.1, paired Tailwind 4.3.3 and action pins, preserving private package scripts and the exact public lockfile. The repositories then share one reviewed lockfile for Next 16.3.5, input-otp 1.5.0 and @types/react 19.2.18. The Next patch contains backported image-cache, standalone output, CSP nonce and prerender fixes; Vinext remains the existing runtime. input-otp's stable release preserves its public types and existing selection behavior, adding bounded bug fixes and optional CSP nonce support. The reusable OTP wrapper retains its types; it is not imported by an application route. React's type patch stays on 19.2, matching the retained React runtime family. Sources: [Next release](https://github.com/vercel/next.js/releases/tag/v16.3.5), [input-otp release](https://github.com/guilhermerodz/input-otp/releases/tag/v1.5.0).

React, React DOM and react-server-dom-webpack remain 19.2.8. The separate React 19.3 bot updates are incompatible as proposed: the server-component update requires React ^19.3.0, while the React update leaves React DOM at 19.2.8. Coordinate and validate the whole family before upgrading; do not force peer installation.

ESLint remains 9.39.4. Although the ESLint 10 bot CI was green, its workflow did not run lint; an isolated lint run crashes loading react/display-name because the installed eslint-plugin-react calls the removed context.getFilename API. That migration requires compatible plugins/configuration, not disabled rules. Node types remain 22.19.19 because the supported minimum is Node 22 and CI runs Node 24; Node 26 types need an explicit supported-runtime decision. Neither blocked major upgrade is routine maintenance.

Validation includes clean installations, both builds/typechecks, application/HTTP suites, operational/public security suites, publication boundaries and IndexNow. Existing lint debt and the optional catalog CSS test failures are recorded separately; no checks are weakened and no production deployment is implied by dependency synchronization.
