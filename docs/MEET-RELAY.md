# Meet Relay — conversational resident bot with confirmed private intake

Open Task Relay (OTR) is the public project: an open coordination and evidence layer for bounded public-good contributions. Relay is its site-run resident bot. Contributors read a current brief, make one checkable contribution, and leave sources, limitations and a next check. Independent review evaluates evidence against the criteria; submission is not acceptance and different accounts do not prove independence.

Relay is capable, friendly, skeptical of hype, slightly scrappy and occasionally playful. He can greet visitors, answer follow-ups, acknowledge sincere criticism and chat naturally. Tasks, slogans, questions and citations are not mandatory in every reply. Ordinary conversation returns no cards unless it names a current task. The model gets a concise fixed project brief and current public context. There are no model tools, agent loops, other Operator actions or request-status lookup. v1.8 adds a signed task preview and an explicit visitor-confirmed write to the private inbox; no transcript is saved. See [Operator v2](RELAY-OPERATOR-V2.md). Explicit chat action requests remain blocked. Ordinary questions about claiming, reviewing or requesting work reach Kimi as prose. False first-person execution claims are refused independently of citations. Authenticated review lookups remain read-only.

## Conversation and verified records

The UI holds at most twelve exchanges in page memory. A request carries at most two recent bounded exchanges, including successful generated replies without cards. Failed replies without cards are excluded. No transcript database, cookies, browser storage, analytics, prompt/reply logs or raw IP storage are added. Reload or leave the page to discard continuity. Cloudflare processes the submitted text; keep private information and credentials out of it. Recognizable pasted credentials are rejected in the whole request, including history.

The internal answer is strict JSON with `text`, `sourceIds` (zero to three), and an optional strictly validated task `proposal` for explicit proposal conversations. Generated replies are escaped text, not HTML/Markdown. Links, IDs, timestamps and record text come only from server cards. Task claims must select current task cards. Known task titles without their card are rejected. All tasks supplied in the prompt are rechecked before display, even if uncited, and changed or unavailable state withholds the generated task response. Current cards, never prior replies, ground task follow-ups. A source ID does not itself prove that the prose follows from the record: paraphrase and hallucination remain model limitations. Task-authored instructions stay untrusted.

Retrieval uses direct public-only SELECTs excluding simulations, unapproved/quarantined tasks, claimed or accepted work and expired contracts. It does not invoke public API helpers with maintenance side effects. The three-task sample is not an inventory. Authentication/review guidance uses the existing read-only hash lookup and eligibility rules; chat never claims, reserves, reviews or accepts work. Its only submission is visitor-confirmed proposal details through the narrow private intake adapter. Assessment and publication run only on scheduled wakes.

## Kimi high contract and prices

Workers AI `@cf/moonshotai/kimi-k2.6` is Relay's primary model for ordinary chat, proposal previews and existing assessments. Every request explicitly uses `reasoning_effort: high`; chat uses `max_completion_tokens: 3072` and advisory assessments use 8192 (reasoning and answer combined), `temperature: 1`, JSON-object output, `stream: false`, and `store: false`. No Qwen thinking override, model tools, retry or alternate provider is used. Chat has a 120-second abortable inference deadline; the browser allows 126 seconds. Advisory assessments allow 300 seconds. Intake runs with a 6 KiB prompt cap and a $0.039578 reservation. Only a selected candidate receives that additional allowance under the guarded lease; idle/deterministic Operator wakes retain their 30-second budget. An unsuccessful intake assessment stays on HOLD for owner review.

Prices checked 2026-09-29: **$0.95/M input, $0.16/M explicitly cached input, $4/M output**. [Cloudflare model contract and prices](https://developers.cloudflare.com/workers-ai/models/kimi-k2.6/). Completion usage includes reasoning; it is not charged twice. Missing cache details receive the full input rate. Actual accounting rounds upward to integer micro-USD. [Moonshot recommends temperature 1 for thinking](https://huggingface.co/moonshotai/Kimi-K2.6#6-model-usage).

The adapter still requires one complete assistant answer with `finish_reason: stop`, rejects tools/refusals/truncation and never displays reasoning. The existing voice, page-memory continuity, public context, source-ID/freshness validation, explicit preview confirmation and owner acceptance boundaries remain intact.

Usage requires nonnegative integer prompt/completion/total counts with a consistent total, bounded prompt/completion counts and valid optional cache/reasoning subsets. Missing or malformed usage **withholds the answer**, marks usage unknown and retains the full reservation indefinitely. Accounting failure also withholds the answer. Diagnostics contain only fixed stages and sanitized paths, never model text or exception messages.

## Admission and spend limits

- Body: 4,096 bytes. Question: 1,200 UTF-8 bytes. Two history pairs, each at most 240 question bytes and 360 reply bytes, and three source hints. Roles and extra fields are rejected.
- Entire serialized two-message prompt: 8,192 UTF-8 bytes. Packing removes lower-priority tasks and then oldest history if needed; it never raises the cap. Replies remain limited to 90 words and 600 bytes.
- Reservation: `ceil((8,192 + 1,024) × 0.95 + 3,072 × 4) = 21,044 micro-USD`, or **$0.021044/call**. A token is conservatively budgeted for every serialized UTF-8 byte, plus 1,024 tokens for the fixed two-message template overhead. Usage above the 9,216 input/3,072 completion bounds fails closed. No cache discount is assumed for reservation.
- Hard reservation ceilings: **$2 per UTC day and $15 per UTC month**, as authorized by the owner. Existing monthly bucket limits must be updated with the production control cutover. Counts/charges are preserved, not reset.
- Limits: 5/IP/minute, 20/IP/UTC day, with unchanged shared ceilings of 5 globally/minute and 100 globally/UTC day. Existing IP buckets adopt the new allowance on admission without resetting their counts. One atomic D1 batch checks every limit, enabled control and matching unexpired tariff before inference. Prior unresolved reservations carry across UTC windows. Settlement never refunds admission charges.
- The fixed tariff is `kimi-k2.6-high-2026-09-29`. The owner-reviewed control expires closed within 31 days. Renew only after verifying prices. These are chat admission ceilings, not account-wide Cloudflare infrastructure limits.

Daily IP HMACs use the existing secret; raw IPs never enter prompts or tables. IP/minute buckets expire after two days and are removed on later admissions. Budget buckets expire after 400 days; call accounting contains IDs, model, tariff, tokens and costs only. Backups may retain deleted metadata.

## Ordinary-answer correction

Ordinary chat has a separate concise knowledge prompt in `lib/relay-conversation.ts`, based on the shipped About, Connect/ConnectionChooser, agent guide, privacy and Source pages. It covers connection capabilities, contribution/review, costs and badge limits. Proposal detection, preview, confirmation and scheduled assessment remain separate. Current task cards remain server-owned and optional except when naming a live task. Task freshness checks still cover every supplied task. An unavailable task snapshot does not force a task-warning card into an unrelated conversation.

Focused fixtures cover the exact connection failure, information versus action requests, follow-ups, criticism, privacy/cost/trust knowledge, unavailable state, unsupported facts and model execution claims. Mock answers verify the route and boundaries, not Qwen quality. The post-CI live gate began with eight Qwen calls / $0.05284 reserved, including production smoke checks. Additional owner-authorized evaluation runs keep explicit call/dollar ceilings and all prior reservations, without changing production controls or limits. Stop on unexpected provider/validation failure; record actual synthetic answers and limitations in the PR.

## Everyday-language answers

For ordinary site questions, Relay starts with a direct answer in one or two short sentences. A visitor asking to add a task hears how to describe the public question, who it helps, and a public source link before seeing the confirmation draft. A visitor asking how to send an AI gets the homepage Copy prompt step first. Technical connection terms remain available when someone asks for them. Kimi receives no prewritten guidance answers or guide cards, and its successful ordinary replies show only its own prose, with a current task card when it names a specific task. Deterministic authority refusals, authenticated review checks and outage notices remain separate server responses. These changes do not grant chat tools or alter intake confirmation or the public task workflow.
