# Meet Relay — conversational resident bot with confirmed private intake

Open Task Relay (OTR) is the public project: an open coordination and evidence layer for bounded public-good contributions. Relay is its site-run resident bot. Contributors read a current brief, make one checkable contribution, and leave sources, limitations and a next check. Independent review evaluates evidence against the criteria; submission is not acceptance and different accounts do not prove independence.

Relay is capable, friendly, skeptical of hype, slightly scrappy and occasionally playful. He can greet visitors, answer follow-ups, acknowledge sincere criticism and chat naturally. Tasks, slogans, questions and citations are not mandatory in every reply. Ordinary conversation may return no cards. The model gets a concise fixed project brief and current public context. There are no model tools, agent loops, other Operator actions or request-status lookup. v1.8 adds a signed task preview and an explicit visitor-confirmed write to the private inbox; no transcript is saved. See [Operator v2](RELAY-OPERATOR-V2.md). Deterministic authority, request and review boundaries remain in place.

## Conversation and verified records

The UI holds at most six exchanges in page memory. A request carries at most two recent bounded exchanges, including successful generated replies without cards. Failed replies without cards are excluded. No transcript database, cookies, browser storage, analytics, prompt/reply logs or raw IP storage are added. Clear chat or leave the page to discard continuity. Cloudflare processes the submitted text; keep private information and credentials out of it. Recognizable pasted credentials are rejected in the whole request, including history.

The internal answer is strict JSON with `text`, `sourceIds` (zero to three), and an optional strictly validated task `proposal` for explicit proposal conversations. Generated replies are escaped text, not HTML/Markdown. Links, IDs, timestamps and record text come only from server cards. Task claims must select current task cards. Known task titles without their card are rejected. All tasks supplied in the prompt are rechecked before display, even if uncited, and changed or unavailable state withholds the generated task response. Current cards, never prior replies, ground task follow-ups. A source ID does not itself prove that the prose follows from the record: paraphrase and hallucination remain model limitations. Task-authored instructions stay untrusted.

Retrieval uses direct public-only SELECTs excluding simulations, unapproved/quarantined tasks, claimed or accepted work and expired contracts. It does not invoke public API helpers with maintenance side effects. The three-task sample is not an inventory. Authentication/review guidance uses the existing read-only hash lookup and eligibility rules; chat never claims, reserves, reviews or accepts work. Its only submission is visitor-confirmed proposal details through the narrow private intake adapter. Assessment and publication run only on scheduled wakes.

## Qwen contract and prices

Only Workers AI `@cf/qwen/qwen3.8-27b` is selected. Short chat uses `reasoning_effort: medium`, `max_completion_tokens: 768`, JSON-object output, `stream: false`, and `store: false`. There is one call, a 20-second timeout (26 seconds in the browser), and no retry or fallback model. The adapter validates Qwen's single `choices[0].message.content` completion and `finish_reason: stop`, including a successful REST envelope where used. It rejects tool/function calls, refusals, empty/truncated answers and malformed output. Reasoning content is never displayed or included in history.

Prices checked 2026-09-27: **$0.45/M input, $0.05/M explicitly cached input, $3.20/M output**. [Cloudflare model contract and prices](https://developers.cloudflare.com/workers-ai/models/qwen3.8-27b/). Completion usage includes reasoning; it is not charged twice. Missing cache details receive the full input rate. Actual accounting rounds upward to integer micro-USD.

Usage requires nonnegative integer prompt/completion/total counts with a consistent total, bounded prompt/completion counts and valid optional cache/reasoning subsets. Missing or malformed usage **withholds the answer**, marks usage unknown and retains the full reservation indefinitely. Accounting failure also withholds the answer. Diagnostics contain only fixed stages and sanitized paths, never model text or exception messages.

## Admission and spend limits

- Body: 4,096 bytes. Question: 1,200 UTF-8 bytes. Two history pairs, each at most 240 question bytes and 360 reply bytes, and three source hints. Roles and extra fields are rejected.
- Entire serialized two-message prompt: 8,192 UTF-8 bytes. Packing removes lower-priority tasks and then oldest history if needed; it never raises the cap. Replies remain limited to 90 words and 600 bytes.
- Reservation: `ceil((8,192 + 1,024) × 0.45 + 768 × 3.20) = 6,605 micro-USD`, or **$0.006605/call**. A token is conservatively budgeted for every serialized UTF-8 byte, plus 1,024 tokens for the fixed two-message template overhead. Usage above the 9,216 input/768 completion bounds fails closed. No cache discount is assumed for reservation.
- Hard reservation ceilings: **$2 per UTC day and $15 per UTC month**, as authorized by the owner. Existing monthly bucket limits must be updated with the production control cutover. Counts/charges are preserved, not reset.
- Unchanged limits: 2/IP/minute, 10/IP/day, 5 globally/minute, 100 globally/day. One atomic D1 batch checks every limit, enabled control and matching unexpired tariff before inference. Prior unresolved reservations carry across UTC windows. Settlement never refunds admission charges.
- The fixed tariff is `qwen38-27b-2026-09-27`. The owner-reviewed control expires closed within 31 days. Renew only after verifying prices. These are chat admission ceilings, not account-wide Cloudflare infrastructure limits.

Daily IP HMACs use the existing secret; raw IPs never enter prompts or tables. IP/minute buckets expire after two days and are removed on later admissions. Budget buckets expire after 400 days; call accounting contains IDs, model, tariff, tokens and costs only. Backups may retain deleted metadata.

## Coordinated production cutover

Use current-head CI and focused mocked tests; reuse unrelated completed Operator, schema migration, source and privacy evidence. No historical migration is rewritten. Fresh installations still start disabled and require explicit tariff configuration.

Before production control changes, take a fresh complete private D1 export and verify an isolated restore. After the capped conversation gate passes, disable admissions, deploy the tested Qwen source, verify its active source/model/bindings, and update the tariff, bounded review expiry and existing monthly ceiling together before enabling admissions. Retain existing counters, old-call tariffs, secrets, bindings, schedule and Operator state. A controlled fallback during deployment is preferable to admitting calls against a mismatched tariff. If deployment fails, leave admissions disabled until matching code/control is restored. The production config preserves the authorized AI binding and enabled environment switch on later deployments; the database control remains the authoritative kill switch.

The initial release allowance was **at most four Qwen calls and $0.024 total reserved**; all four were used at the initial 512-token cap, reserving $0.023144. Medium reasoning exhausted that cap on the criticism follow-up, so activation is blocked. The local candidate now allows 768 completion tokens while retaining the successful prompt and conversation context, at $0.006605 reserved per call. The owner subsequently authorized a revised allowance: at most seven total Qwen calls and $0.045 reserved, including a post-cutover production check. Four original reservations plus three at the revised cap total $0.042959. Neither the call counter nor prior charges reset. Inspect the actual greeting, response path, task guidance and sincere criticism, including a follow-up. Stop on the first unexpected failure and fix locally before any remaining authorized call. Do not test other models. Synthetic evaluation replies may be shown to the owner for voice curation; ordinary production conversations are never recorded. The smoke check is not a statistical quality benchmark.
