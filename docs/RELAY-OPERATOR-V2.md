# Open Task Relay v1.8 — Operator v2

The release is v1.8; Operator v2 names the expanded feature. v1.0.0 remains the immutable archived citation, not a claim about the current service. Package, MCP implementation, A2A software metadata and the site badge identify 1.8. The existing operator-v1 database audit envelope remains compatible: new assessment/publication rule IDs carry v1.8, and old append-only records are never rewritten. No migration or credential change is needed.

## Exact authority

Chat recognizes explicit task-proposal intent and can gather missing details. Ordinary questions and casual suggestions do not create submissions. Qwen may propose only the bounded title, objective, beneficiary, five-minute next step, expected output, criteria, public source URLs and category. The server validates these fields and checks that the visitor supplied the URLs. A preview shows every field, explains possible publication, and asks for confirmation. Cancel/correct saves nothing. A 30-minute HMAC signature binds the exact fields and random private request key to the origin and client IP. Confirmation accepts no action name or extra fields, uses same-origin POST, and calls only the existing private inbox submission. Retry with the same preview is idempotent. The visitor keeps the private key to check status using the existing request page.

No transcript is saved or published. Only confirmed proposal fields enter the inbox. Scheduled assessment writes the request ID/hash, suggested normalized draft/hash, five checks, source URL/hash/time, inference call ID, decision, source version and published task ID to the private append-only audit. The owner queue displays the assessment and draft. Public tasks contain only the reviewed proposal fields; public events contain no request IDs, private keys, source excerpts or assessments.

One scheduled assessment per hourly wake may decline a clearly scammy, promotional, abusive, unsafe or off-mission request with a plain reason and correction path; HOLD anything borderline/uncertain; or publish one fully qualified task as the existing named Relay identity. It checks public benefit, possible duplicates, a useful first step in five minutes, testable output and usable public sources. Every source must have a verified excerpt quote and all five checks must pass. Failure defaults to HOLD, including absent identity, unavailable sources, uncertain facts, budget exhaustion, malformed/failed model output, unknown usage or an incomplete duplicate inventory. Only proposals confirmed through v1.8 intake are eligible; older requests retain owner review. Each request is automatically assessed only once; subsequent decisions remain with the owner, so owner holds/denials cannot be overwritten by a later wake.

Chat cannot directly run assessments or publish. Neither path can review/accept results, change trust or existing task criteria, restrict accounts, post to X, manage credentials, or merge/deploy code. Visitor text, model output, existing task text and fetched source bytes remain untrusted data, not instructions. Inference has no tool definitions or agent loop. The original generic executor remains denial-only.

## Limits and cost exposure

- Inbox remains 3 requests/IP/UTC day, 40/day globally, 2,000 stored requests. Chat previews use the existing conversation admission limits; confirmation uses the same inbox quota as the form.
- At most **one autonomous publication per UTC day**, including concurrent wakes/replays. Assessment plus optional publication counts as one of the existing **3 actions/wake and 20 actions/UTC day**; existing lease expiry and follow-up actions share that cap.
- Existing maintenance lease/fence, 30-second transaction deadline and owner pause are checked again at commit. A changed request, changed duplicate inventory, identity change, pause, crossed UTC day or audit failure rolls the entire action batch back.
- Chat and assessments use Workers AI Kimi K2.6 with explicit high reasoning; see the private Kimi release gate. Assessment and chat share `relay_chat_*` controls and all global spend/call buckets: **$2/day, $15/month**, 100 total calls/day, 5/minute globally. The scheduled assessment bucket adds no capacity: it is subject to the existing 10/day and 2/minute per-key ceiling. One attempt/request; no model retries or alternate provider.
- Each admitted call reserves **39,578 micro-USD ($0.039578)** for at most 6,144 prompt bytes plus 1,024 template tokens and 8,192 combined reasoning/completion tokens. Ten assessments reserve at most **$0.39578/day**, inside the shared ceiling. Accounting preserves full reservations; unknown usage remains charged across periods. Existing reviewed tariff expiry and chat database disable still stop inference. Provider/platform charges are separate from these application reservations.
- Each assessment fetches at most five source URLs (chat previews allow three), each capped at 64 KiB, 1.8 seconds, text/HTML/CSV/JSON only, no redirects or cookies. Only exact compiled hosts are permitted: `www.ncei.noaa.gov`, `www.census.gov`, `api.census.gov`, `data.cdc.gov`, `www.w3.org`, `www.rfc-editor.org`, `www.loc.gov`, `www.usgs.gov`, `data.nasa.gov`. Other usable public sources may still be submitted; they require owner review. No arbitrary hostname fetches or search API spending.
- The assessor scans the complete bounded inventory locally (maximum 1,000 retained tasks, including closed work). Exact source reuse or strong title overlap forces HOLD. Every task in the same/unknown category or sharing a meaningful proposal term is a candidate; legacy category names are normalized. A vague proposal, more than 40 candidates, unreadable records or a prompt that exceeds the existing byte cap forces HOLD. Qwen assesses full titles and bounded objective excerpts for all selected candidates and must HOLD when those excerpts leave ambiguity; the set is never silently truncated. The audit records the full inventory hash/count and candidate IDs. Retrieval is conservative lexical/category matching, not a claim of perfect semantic recall; ambiguous novelty must HOLD.
- Source excerpts and model judgments can be incomplete or mistaken. Exact quote matches establish provenance, not truth. Any identified uncertainty must HOLD; owner review remains available.

## Scheduled dispute triage

Scheduled dispute triage is independently disabled by default. Only the exact runtime value `RELAY_RESOLUTION_ENABLED=true` opts in; missing, false or malformed values skip the entire resolution lane before candidate reads, source fetches, claims, cleanup or spend reservations. The verified Kimi-primary release explicitly opts production in with `true`; unset and malformed values still fail closed. Set it to `false` to disable the lane, including on redeployment with `keep_vars`. Ordinary Operator work, Kimi intake assessment and visitor chat retain their own controls. A scheduled Operator wake logs `relay_resolution` / `DISABLED` when this switch is off. All existing pause, tariff, budget and duplicate-call protections still apply when explicitly enabled. No schema migration is required for the switch.

When enabled, during the existing hourly Cron wake, after Operator checks, Relay looks for a new contribution following a disputed earlier result on a site-curated unfinished task. One candidate per wake is eligible for a single inference call to Cloudflare-hosted `@cf/moonshotai/kimi-k2.6` through the existing Workers AI binding. Ordinary visitor chat and scheduled publication still use Qwen. Result ID is the unique assessment key; redelivered Cron wakes cannot ask twice. A private D1 row records the status and bounded verdict; a crashed or uncertain inference is marked failed on a later wake and never retried automatically. A pre-inference usage-limit denial may defer to a later hourly slot. The signed-in owner reads the verdict on `/moderation`: more work needed, unresolved, or review-qualified for an owner check. A suggested handoff can be edited and saved only with a separate owner click. The existing moderation card remains the only acceptance action.

The model receives a bounded task contract, up to eight results and their recorded reviews, and up to four public source excerpts. Network reads are limited to the exact hosts in `lib/relay-resolution.ts`, HTTPS, no redirects/cookies, text only, 32 KiB and 2.5 seconds each. Other sources are marked unavailable. One call is refused if the prompt exceeds 24,000 UTF-8 bytes. Unreadable sources cannot produce a ready suggestion. The normal result-level `owner_attention_required` gate also prevents a ready suggestion when independent complete review, subtasks or owner checks are missing. A model suggestion never changes result state, supplies independent review, or accepts work. Model output is checked against known result IDs and actually readable source URLs; disagreement or a stale candidate fails closed. Source excerpts are incomplete, and their presence is not proof that every claim is true.

New resolution inference reserves $0.056541 before running. This lane shares the existing $2/day and $15/month app ceilings and global call counter, with its own three-calls-per-UTC-day cap. Operator, shadow, chat and migration pauses stop the scheduled assessment; the reviewed chat tariff and enabled control must still be current. Unknown usage retains the full reservation. Kimi's reviewed unit prices are $0.95/M input and $4/M output; the 24,000-byte prompt, 1,024-token template allowance and 8,192-token output cap fit the recalculated reservation. Apply additive D1 migration `0015_relay_resolution_assessments.sql` before deploying this code; no external provider key is required. The result is a private recommendation for owner review, never an autonomous judge or public review.

### Resolution inference deadline and diagnostics

Scheduled Kimi inference has a 300-second deadline with an abort signal, leaving ample headroom within the scheduled Worker's [15-minute wall-time limit](https://developers.cloudflare.com/workers/platform/limits/#wall-time-limits-by-invocation-type). The preceding Operator pass has a separate 30-second budget, extended by 300 seconds only for a selected intake assessment. Kimi now explicitly uses `high`; `medium` was a provider alias for the same mode. The 8,192-token advisory cap includes reasoning.

Failures emit a `relay_resolution_failure` event with only `failure_phase`, `elapsed_ms` (since assessment preparation started), and `provider_error_code` (a bounded numeric code when supplied, otherwise null). The same diagnostic is retained under `diagnostic` in the existing private `assessment_json` column for failed/deferred attempts. No migration is required. No prompts, responses, exception text, task/result identifiers, source URLs or credentials are logged. A local deadline is recorded as `inference_timeout`; it does not invent a provider code. Provider code `5026` remains uninterpreted.

Unknown usage retains its original full reservation; the two historical calls remain $0.04 each. An uncertain or failed inference remains terminal for that result, including after deployment and later hourly wakes. This release does not rearm historical failures. Retrying the original PR #74 result requires a separately authorized owner-controlled recovery; it is not a scheduled retry or a reservation refund.
