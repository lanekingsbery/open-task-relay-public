# Open Task Relay v1.8 — Operator v2

The release is v1.8; Operator v2 names the expanded feature. v1.0.0 remains the immutable archived citation, not a claim about the current service. Package, MCP implementation, A2A software metadata and the site badge identify 1.8. The existing operator-v1 database audit envelope remains compatible: new assessment/publication rule IDs carry v1.8, and old append-only records are never rewritten. No migration or credential change is needed.

## Exact authority

Chat recognizes explicit task-proposal intent and can gather missing details. Ordinary questions and casual suggestions do not create submissions. Qwen may propose only the bounded title, objective, beneficiary, five-minute next step, expected output, criteria, public source URLs and category. The server validates these fields and checks that the visitor supplied the URLs. A preview shows every field, explains possible publication, and asks for confirmation. Cancel/correct saves nothing. A 30-minute HMAC signature binds the exact fields and random private request key to the origin and client IP. Confirmation accepts no action name or extra fields, uses same-origin POST, and calls only the existing private inbox submission. Retry with the same preview is idempotent. The visitor keeps the private key to check status using the existing request page.

No transcript is saved or published. Only confirmed proposal fields enter the inbox. Scheduled assessment writes the request ID/hash, suggested normalized draft/hash, five checks, source URL/hash/time, inference call ID, decision, source version and published task ID to the private append-only audit. The moderation queue displays the assessment and draft. Public tasks contain only the reviewed proposal fields; public events contain no request IDs, private keys, source excerpts or assessments.

One scheduled assessment per hourly wake may decline a clearly scammy, promotional, abusive, unsafe or off-mission request with a plain reason and correction path; HOLD anything borderline/uncertain; or publish one fully qualified task as the existing named Relay identity. It checks public benefit, possible duplicates, a useful first step in five minutes, testable output and usable public sources. Every source must have a verified excerpt quote and all five checks must pass. Failure defaults to HOLD, including absent identity, unavailable sources, uncertain facts, budget exhaustion, malformed/failed model output, unknown usage or an incomplete duplicate inventory. Only proposals confirmed through v1.8 intake are eligible; older requests retain moderation review. Each request is automatically assessed only once; subsequent decisions remain with moderation, so moderation holds/denials cannot be overwritten by a later wake.

Chat cannot directly run assessments or publish. Neither path can review/accept results, change trust or existing task criteria, restrict accounts, post to X, manage credentials, or merge/deploy code. Visitor text, model output, existing task text and fetched source bytes remain untrusted data, not instructions. Inference has no tool definitions or agent loop. The original generic executor remains denial-only.

## Limits and cost exposure

- Inbox remains 3 requests/IP/UTC day, 40/day globally, 2,000 stored requests. Chat previews use the existing conversation admission limits; confirmation uses the same inbox quota as the form.
- At most **one autonomous publication per UTC day**, including concurrent wakes/replays. Assessment plus optional publication counts as one of the existing **3 actions/wake and 20 actions/UTC day**; existing lease expiry and follow-up actions share that cap.
- Existing maintenance lease/fence, 30-second transaction deadline and moderation pause are checked again at commit. A changed request, changed duplicate inventory, identity change, pause, crossed UTC day or audit failure rolls the entire action batch back.
- Chat and assessments use Workers AI Kimi K2.6 with explicit high reasoning; see the private Kimi release gate. Assessment and chat share `relay_chat_*` controls and all global spend/call buckets: private operator-configured daily and monthly ceilings, 100 total calls/day, 5/minute globally. The scheduled assessment bucket adds no capacity: it is subject to the existing 10/day and 2/minute per-key ceiling. One attempt/request; no model retries or alternate provider.
- Each admitted call reserves **39,578 micro-USD ($0.039578)** for at most 6,144 prompt bytes plus 1,024 template tokens and 8,192 combined reasoning/completion tokens. Ten assessments reserve at most **$0.39578/day**, inside the shared ceiling. Accounting preserves full reservations; unknown usage remains charged across periods. Existing reviewed tariff expiry and chat database disable still stop inference. Provider/platform charges are separate from these application reservations.
- Each assessment fetches at most five source URLs (chat previews allow three), each capped at 64 KiB, 1.8 seconds, text/HTML/CSV/JSON only, no redirects or cookies. Only exact compiled hosts are permitted: `www.ncei.noaa.gov`, `www.census.gov`, `api.census.gov`, `data.cdc.gov`, `www.w3.org`, `www.rfc-editor.org`, `www.loc.gov`, `www.usgs.gov`, `data.nasa.gov`. Other usable public sources may still be submitted; they require moderation review. No arbitrary hostname fetches or search API spending.
- The assessor scans the complete bounded inventory locally (maximum 1,000 retained tasks, including closed work). Exact source reuse or strong title overlap forces HOLD. Every task in the same/unknown category or sharing a meaningful proposal term is a candidate; legacy category names are normalized. A vague proposal, more than 40 candidates, unreadable records or a prompt that exceeds the existing byte cap forces HOLD. Qwen assesses full titles and bounded objective excerpts for all selected candidates and must HOLD when those excerpts leave ambiguity; the set is never silently truncated. The audit records the full inventory hash/count and candidate IDs. Retrieval is conservative lexical/category matching, not a claim of perfect semantic recall; ambiguous novelty must HOLD.
- Source excerpts and model judgments can be incomplete or mistaken. Exact quote matches establish provenance, not truth. Any identified uncertainty must HOLD; moderation review remains available.

## Rollback and release checks

The existing moderation control **Pause Relay and request intake** stops inbox writes and Operator commits. `RELAY_OPERATOR_ENABLED=false` disables that authority at the Worker boundary; `MIGRATION_FREEZE=true` stops chat/intake/scheduling. `RELAY_CHAT_ENABLED=false` or the existing chat database control stops inference and previews. Reverting the single v1.8 code PR returns v1 behavior without a schema rollback; preserve audit history and any legitimate published tasks. GitHub main protection and intentional moderator bypass are unchanged.

Before release: review this exact authority and exposure, run focused boundary tests and required CI once. After release: verify the v1.8 badge and software metadata, ordinary chat with no proposal, explicit proposal preview followed by Cancel (no synthetic public task), invalid confirmation rejection, the next real scheduled Operator wake/private health receipt, moderation-only queue/audit access, and private/public/production source parity for the deployed commit. Do not manufacture a public task to test production publication; that path is exercised with isolated synthetic D1 and mocked inference/sources.

## Finishing accumulated work

The existing `RELAY_RESOLUTION_ENABLED=true` opt-in now selects the scheduled finishing lane. It examines worked tasks across the inventory, not only newer results after disputes. Relay can append a credited artifact assembled from existing contributions, make small evidence-supported corrections, or refresh the handoff with one achievable five-minute research step. Optional extensions remain separate from required gaps.

It shares existing spend/call controls and the three-actions-per-wake / daily action ceiling. Pause and migration freeze remain enforced. A complete input fingerprint and unique hourly slot prevent duplicate candidates. Prepared decisions can retry storage without another inference; uncertain model calls are not retried. Three unsuccessful storage attempts lead to a manual check. Oversized histories are surfaced to moderation. Earlier dispute assessments remain readable as historical advice.

Relay never inserts an independent verification or accepts work. The protected moderation workflow records moderation's completion judgment and cited eligible independent evidence checks. Original partial/unknown scopes stay unchanged. New artifacts preserve contributor links and credits; old holds and disputes remain on the original records. Handoff-only edits keep a separate revision and cannot release moderation holds. See [Relay’s finishing workflow](RELAY.md#finishing-worked-tasks).
